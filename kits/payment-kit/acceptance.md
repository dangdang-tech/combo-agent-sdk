# Payment Kit 接入验收表

kit 自身的配置检查和 SDK 回归可离线完成。下表所有商业链路初始状态均为 **NOT_RUN**；创建本 kit 或 CI 通过不改变这些状态。

| 编号 | 要证明的行为 | 必须留下的证据 | 初始状态 |
| --- | --- | --- | --- |
| K01 | 受权限控制地发布目录，价格/点数分开；变价不改变旧订单 | 两版目录及旧订单快照，越权改价被拒绝 | NOT_RUN |
| K02 | 新手奖励符合条件且只发一次；关闭试用也可运行 | 同一用户重复/并发领取只有一个发放记录，0 点配置 | NOT_RUN |
| K03 | 用户主动购买套餐，无需先调用模型 | Host 操作、平台订单、渠道确认与点数到账关联 | NOT_RUN |
| K04 | 伪造金额、点数、收款人或篡改返回 URL 不会发点 | 请求被拒或按权威快照处理；无额外账目 | NOT_RUN |
| K05 | 重复回调、并发确认、超时和刷新不重复下单/到账 | 原幂等编号、唯一支付与发放记录；关闭浏览器后也能恢复 | NOT_RUN |
| K06 | 标准与高级两个不同业务动作按各自价格结算 | 原请求、operationId、服务版本、点数余额与消费账 | NOT_RUN |
| K07 | 一个动作内部多次模型/工具调用，只结算一次服务费 | 一个消费记录对应多个 callId 和独立成本记录 | NOT_RUN |
| K08 | 最后少量点数被并发请求争用时不会超扣 | 事务/预留结果和最终余额；不足的任务未开始执行 | NOT_RUN |
| K09 | 支付后继续、重复点击、同 ID 异参、跨用户/Agent 恢复 | 原结果复用；异参冲突与越权拒绝；无第二次执行 | NOT_RUN |
| K10 | 已知失败释放；执行未知保留并核对；结算未知只查询/重放结算 | 三种故障注入后的状态、预留、结果与账本；重启后可恢复 | NOT_RUN |
| K11 | 过期、退款、拒付和已消费/赠送点数按发布政策处理 | 版本化政策、原批次、调整账与创作者应收的对应 | NOT_RUN |
| K12 | 购买点数、赠送点数、底层成本与创作者应收分开 | 一条从资金到服务消费再到应收的对账链；赠送不凭空变现金 | NOT_RUN |
| K13 | 一位新创作者仅靠 SDK、文档和必要配置接入自己的 Agent | 锁定工件、独立操作记录，无维护者临时补代码或改账 | NOT_RUN |
| K14 | 一位真实用户购买并拿到真实可用服务结果 | 经授权的真实交易、一次到账与一次消费的脱敏关联证据 | NOT_RUN |
| K15 | 该笔收入归属正确的创作者并实际到账 | 选定收款路径、订单/结算单、脱敏付款及到账核验 | NOT_RUN |

使用测试替身完成 K03–K12 可报告 `simulated_platform_flow`，不能因此将真实交易 K14 或实际到账 K15 标为 PASS。仅有平台商户收到充值不能替代 K15；若采用创作者直收，也需要正确商户绑定和创作者到账证明。

## 交接记录模板

```text
SDK 完整提交 SHA / 版本：
SDK 安装包 SHA-256：
平台候选 SHA / 部署版本 / 环境：
Agent 版本：
目录版本 / 点数范围 / 政策版本：
收款路径及经核验主体（脱敏）：
执行人 / 时间 / 证据来源：

kit 配置结构与跨字段检查：PASS / FAIL
SDK 回归与协议检查：PASS / FAIL / NOT_RUN
平台商业合同实现：IMPLEMENTED / PARTIAL / NOT_IMPLEMENTED
测试替身行为检查 K01–K12：逐项记录
受限 Test 环境 K01–K12：逐项记录
陌生接入者 K13：PASS / FAIL / NOT_RUN
真实用户交易与服务 K14：PASS / FAIL / NOT_RUN
创作者实际到账 K15：PASS / FAIL / NOT_RUN

脱敏关联：订单 → 支付 → 额度批次 → 消费 → operationId
          → 底层成本 → 创作者应收/收款归属 → 结算/到账
未决政策、失败步骤、错误码与下一责任方：
```

真实交易前另行确认付款方、收款方、金额上限与环境操作授权。凭据、支付 token、Cookie、原始聊天和完整银行流水不进入公共仓库；验收保留最少必要的脱敏编号和证明。
